Uncertainty-Guided Active Exploration

🎯 NeurIPS / ICML Độ khó: Trung bình

🔍 Vấn đề — "BFS mù"

❌ Hiện tại

Code trong graph.py dòng 79:

return self.unexplored_nodes[0] #TODO: Can add user-defined priortization here.

Mọi node được duyệt theo thứ tự FIFO. Node nào được khám phá trước thì xử lý trước — bất kể node đó có hứa hẹn sinh ra nhiều task hữu ích hay không.

✅ Đề xuất
  • Train một value network nhỏ dự đoán "node X sẽ sinh ra bao nhiêu feasible task?"
  • Dùng UCB (Upper Confidence Bound) — ưu tiên node vừa có expected value cao vừa có uncertainty lớn
  • Giống như Multi-Armed Bandit: exploration (node mới, uncertainty cao) vs exploitation (node chắc chắn có nhiều task)
  • Phase 3 cũng adaptive: task nào model đang giải inconsistent → sample thêm

💡 Trực quan hóa

Trước (BFS mù): Sau (UCB-guided): root root ├── /products ← duyệt trước ├── /products (score: 0.7 + 0.3×1.5 = 1.15) ├── /cart ← duyệt sau ├── /deals (score: 0.4 + 0.3×3.0 = 1.30) ← CHỌN! └── /deals ← duyệt cuối └── /cart (score: 0.5 + 0.3×0.8 = 0.74) Tất cả mất 3 episode /deals có uncertainty cao → khám phá trước → tìm được task mới nhanh hơn!

🧬 Code thay đổi

graph.py — get_next_node()
def get_next_node(self, value_estimator=None) -> Node | None: if not self.unexplored_nodes: return None if value_estimator is None: return self.unexplored_nodes[0] # fallback BFS # UCB: expected_value + c × sqrt(ln(total) / visited_count) scores = [] total_visits = len(self.explored_nodes) + 1 for node in self.unexplored_nodes: expected = value_estimator.predict_task_yield(node) uncertainty = np.sqrt(np.log(total_visits) / max(node.visit_count, 1)) scores.append((expected + self.exploration_c * uncertainty, node)) return max(scores, key=lambda x: x[0])[1]
web_explore.py — Phase 3 (adaptive sampling)
def sample_task_solving_trajectories_adaptive( node, agent, evaluator, graph, max_steps, base_samples ): for task in node.get_feasible_tasks(): # Đo uncertainty: task có cả success + failure trajectory? success_rate = task.success_rate() uncertainty = 2 * success_rate * (1 - success_rate) # max at 0.5 n_samples = max(base_samples, int(base_samples * (1 + 2 * uncertainty))) for _ in range(n_samples): traj = run_episode(goal=task.goal, node=node, ...) node.add_trajectory(traj)

Iterative Self-Improving Exploration–Fine-Tuning Loop

🎯 NeurIPS / ICLR Độ khó: Trung bình

🔍 Vấn đề — "One-pass lãng phí"

❌ Hiện tại

Go-Browse chạy đúng 1 lần: GPT-4o/Claude explore → thu data → train 1 model → xong.

Agent dùng để explore (GPT-4o) không bao giờ được cải thiện bởi chính dữ liệu nó thu thập. Model vừa train xong không được dùng để explore tiếp.

✅ Đề xuất
  • Bootstrapping loop: explore → train → dùng model mới explore tiếp → train tiếp → ...
  • Agent càng tốt → khám phá được task khó hơn → data chất lượng cao hơn → agent càng tốt
  • Giống AlphaGo self-play hay RLHF iterative — virtuous cycle
  • Key insight: model vòng 2+ có thể tìm ra task mà GPT-4o bỏ sót

💡 Trực quan hóa — Virtuous Cycle

┌──────────────────────────────────────────────────────────────────┐ │ │ │ VÒNG 1 VÒNG 2 VÒNG 3 │ │ │ │ GPT-4o ──explore──▶ Data₁ π₁ ──explore──▶ Data₂ π₂ ──... │ │ │ │ │ │ │ │ └──train──▶ π₁ ◄─────┘ └──train──▶ π₂ ◄─────┘ │ │ │ │ Data₁: 100K steps Data₂: 130K steps Data₃: 155K │ │ (task đơn giản) (thêm task trung bình) (thêm task khó)│ │ │ │ → Mỗi vòng, agent khám phá được task mà vòng trước bỏ lỡ │ └──────────────────────────────────────────────────────────────────┘

Hierarchical Skill Discovery & Cross-Website Transfer

🎯 ICML / ACL Độ khó: Khó

🔍 Vấn đề — "Mỗi website là một thế giới riêng"

❌ Hiện tại

Mỗi Node trong Graph được xử lý độc lập. Skill "thêm sản phẩm vào cart" học trên amazon.com không tự động transfer sang walmart.com.

Trace chỉ lưu đường đi vật lý giữa 2 URL — không abstract hóa thành reusable skill.

✅ Đề xuất
  • Skill Clustering: Gom các trajectory có action pattern tương tự (dùng edit distance trên chuỗi action types) thành skill clusters
  • Hierarchical Decomposition: Mỗi task = [Navigate to page] + [Execute skill]. Skill được học 1 lần, reuse nhiều website
  • Skill Library: ~50-100 atomic skills (add_to_cart, search_product, fill_form, select_dropdown...)
  • Khi explore website mới: agent chỉ cần học navigation + map task → skill có sẵn

@dataclass class Skill: name: str action_template: list[str] # ["click(dropdown)", "click(option)", ...] preconditions: list[str] # ["page has 'Add to Cart' button"] postconditions: list[str] # ["item appears in cart"] trajectory_ids: list[str] websites: set[str] # {"amazon.com", "walmart.com", ...} def discover_skills(graph: Graph) -> dict[str, Skill]: """Cluster all trajectories across nodes by action sequence similarity.""" all_trajs = [] for node in graph.nodes.values(): for task in node.tasks.values(): all_trajs.extend(task.positive_trajs) # Extract action type sequences: ["click", "type", "click", "send_msg"] sequences = [ [extract_action_type(step.action) for step in traj.steps] for traj in all_trajs ] # Cluster by edit distance → skill groups clusters = agglomerative_clustering(sequences, distance_threshold=0.3) skills = {} for i, cluster in enumerate(clusters): template = compute_consensus_template(cluster) skills[f"skill_{i}"] = Skill( name=name_skill(template), # e.g., "add_to_cart" action_template=template, websites=extract_websites(cluster), ... ) return skills

Verifier Ensemble với Confidence-Calibrated Data Filtering

🎯 NeurIPS / AAAI Độ khó: Dễ

🔍 Vấn đề — "1 evaluator, 0 confidence"

❌ Hiện tại

Code trong evaluator.py: gọi GPT-4V đúng 1 lần → success/failure.

msg_str, _ = self.client.one_step_chat(text=prompt, image=img, ...) trajectory.success = msg_dict["status"].lower() == "success" trajectory.reward = 1.0 if trajectory.success else 0.0

Không có confidence score, không cross-check → false positive/negative trong training data → model học sai.

✅ Đề xuất
  • Multi-Evaluator Ensemble: GPT-4V + Claude-V + Gemini-V cùng evaluate 1 trajectory. Chỉ giữ nếu ≥2/3 agree
  • Soft labeling: trajectory "gây tranh cãi" (2/3 agree) → reward = 0.67 thay vì 0/1. Dùng label smoothing trong training
  • Verifier Distillation: Train 1 verifier nhỏ từ ensemble → evaluation rẻ hơn 10× → evaluate được nhiều data hơn

💡 Trực quan hóa

HIỆN TẠI: ĐỀ XUẤT: GPT-4V ──▶ success ──▶ keep GPT-4V ──▶ success ──┐ (có thể sai!) Claude ──▶ success ──┼──▶ 3/3 agree Gemini ──▶ success ──┘ reward = 1.0 ✓ GPT-4V ──▶ success ──┐ Claude ──▶ success ──┼──▶ 2/3 agree Gemini ──▶ failure ──┘ reward = 0.67 (soft) GPT-4V ──▶ success ──┐ Claude ──▶ failure ──┼──▶ 1/3 agree Gemini ──▶ failure ──┘ → DISCARD ✗ DATA QUALITY: Trước: ~15-20% label noise (GPT-4V hallucination) Sau: ~5-8% label noise (ensemble filtering) → Loại bỏ 40% trajectory nhiễu → model trained tốt hơn rõ rệt

🧬 Code thay đổi

evaluator.py — EnsembleEvaluator
class EnsembleEvaluator: def __init__(self, models=("gpt-4o", "claude-3.5-sonnet", "gemini-1.5-pro")): self.evaluators = [Evaluator(m) for m in models] def evaluate(self, trajectory: Trajectory) -> dict: results = [] for evaluator in self.evaluators: traj_copy = deepcopy(trajectory) evaluator.evaluate(traj_copy) results.append(traj_copy.success) agreement = sum(results) / len(results) # Hard filtering: discard low-agreement trajectories if agreement < 0.34: trajectory.success = False trajectory.reward = 0.0 trajectory.misc["evaluation_quality"] = "discard" return trajectory # Soft labeling trajectory.success = agreement >= 0.67 trajectory.reward = agreement trajectory.misc["evaluation_agreement"] = agreement trajectory.misc["evaluation_quality"] = "high" if agreement == 1.0 else "medium" return trajectory
