🏗️ Tổng quan kiến trúc

Go-Browse là một framework unsupervised web agent training. Ý tưởng cốt lõi: thay vì con người viết từng demonstration, framework tự động khám phá website, đề xuất các task khả thi, giải chúng, và thu thập trajectory thành công làm dữ liệu SFT.

Website → Go-Browse Algorithm → Trajectories (JSON) → HuggingFace Dataset → preprocess.py → SFT / LoRA Training → Fine-tuned Web Agent

Kiến trúc chia làm 3 tầng:

TầngThư mụcVai trò
Explorationwebexp/explore/Khám phá web, thu thập trajectory
Agentswebexp/agents/LLM Agents (Solver, PageExplorer, NavExplorer)
Trainingwebexp/train/SFT & LoRA training trên trajectory đã thu thập

1. Thu thập dữ liệu — Go-Browse Algorithm

[Algorithm] web_explore.py

Input:Config YAML (URL gốc, danh sách agent, max_nodes, allowlist/denylist patterns)
Output:Graph các Node (trang web) đã khám phá, mỗi Node chứa Tasks & Trajectories thành công/thất bại
Entry point:python -m webexp.explore.algorithms.web_explore -c configs/go_browse_config.yaml

🔁 Vòng lặp chính (Main Loop)

while graph còn node chưa explored và chưa đạt max_nodes:
    1. Lấy node tiếp theo từ graph (FIFO)
    2. Reset browser về URL của node đó

    // === PHASE 1: Đề xuất Task ===
    3. PageExplorer agents: duyệt trang, đề xuất task trên trang hiện tại
       → Mỗi agent: run_episode → get_proposed_tasks()
       → Thêm task vào node

    4. NavExplorer agents: tìm navigation (link, button) để đến trang mới
       → Mỗi agent: run_episode → get_proposed_tasks()
       → Nếu tìm thấy URL mới hợp lệ → thêm node mới vào graph

    // === PHASE 2: Lọc Task khả thi ===
    5. Feasibility Checker (SolverAgent) chạy từng task
       → Nếu task giải được (reward > 0) → đánh dấu feasible

    // === PHASE 3: Thu thập Demo ===
    6. Solver agents chạy lại các task feasible
       → Thu thập trajectory (action + thought) thành công
       → Lưu vào node/task

    7. Đánh dấu node đã explored

🎯 Ý tưởng cốt lõi

Giống như BFS trên đồ thị web: mỗi Node là một URL. Từ mỗi node, PageExplorer tìm task có thể làm trên trang đó, NavExplorer tìm đường đến trang mới. Feasibility Checker đảm bảo task thực sự làm được trước khi đưa vào dataset. Đây là cách tạo dữ liệu huấn luyện không cần con người gán nhãn.

2. Cấu trúc dữ liệu cốt lõi

[DataClass] Graph — webexp/explore/core/graph.py

Input:root_url, exp_dir, allowlist_patterns, denylist_patterns
Output:Đồ thị có hướng các Node, quản lý explored/unexplored

Cấu trúc dữ liệu trung tâm. Lưu tất cả node dưới dạng dict {url → Node}. Duyệt theo FIFO từ unexplored_nodes. Có cơ chế allowlist/denylist để kiểm soát URL nào được phép khám phá.

[DataClass] Node — webexp/explore/core/node.py

Input:url, parent (Node), prefixes (list[Trace]), exp_dir
Output:Một node trong đồ thị, chứa tasks & exploration_tasks

Mỗi Node = 1 URL. Chứa 2 loại task: tasks (task đã được verify feasible) và exploration_tasks (task do Explorer agent đề xuất). Có children là các URL mới được NavExplorer tìm thấy. Hỗ trợ save/load toàn bộ trạng thái để resume.

[DataClass] Task — webexp/explore/core/task.py

Input:goal (str), exp_dir
Output:Task với positive_trajs & negative_trajs

Mỗi Task = 1 câu lệnh (vd: "Tìm sản phẩm rẻ nhất trong danh mục"). Lưu các trajectory thành công (positive_trajs) và thất bại (negative_trajs). Hàm is_feasible() trả về True nếu có ít nhất 1 positive trajectory. Có parser để tách [TAG] trong goal string.

[DataClass] Trajectory — webexp/explore/core/trajectory.py

Input:steps (list[TrajectoryStep]), goal, reward, success
Output:Một chuỗi hành động hoàn chỉnh của agent

Mỗi Trajectory = 1 lần agent thực thi 1 task. Chứa danh sách TrajectoryStep (action + thought + observation + screenshot). Có reward (điểm đánh giá thành công) và success (boolean).

[DataClass] TrajectoryStep — webexp/explore/core/trajectory.py

Input:action, parsed_action, thought, observation (dict), misc
Output:1 bước đơn lẻ trong trajectory

Mỗi step = 1 hành động của agent. action là raw output từ LLM, parsed_action là action đã được parse (vd: click('a12')), thought là suy nghĩ của agent, observation chứa axtree, screenshot, DOM.

[DataClass] Trace — webexp/explore/core/trace.py

Input:steps, start_url, end_url
Output:Đường đi từ URL A → URL B

Dùng để lưu "prefix" — chuỗi hành động navigation từ node cha đến node con. Khi cần reset browser về 1 node, ta phát lại Trace này.

[DataClass] BrowserGymAgentTrajectoryData — webexp/agents/trajectory_data.py

Input:steps, goal, reward (từ dữ liệu thô)
Output:Trajectory đã được clean để đưa vào dataset

Đây là lớp quan trọng nhất cho training. process_for_dataset() thực hiện các bước làm sạch:

  1. ✅ Bỏ step có action/thought/axtree bị null
  2. ✅ Nếu step cuối là report_infeasible nhưng reward > 0 → bỏ trajectory (mâu thuẫn)
  3. ✅ Cắt các noop() ở cuối trajectory (hành động thừa)

3. Tiền xử lý dữ liệu — preprocess.py

[Script] preprocess.py

Input:Dataset từ HuggingFace apurvaga/go-browse-wa (hoặc local disk)
Output:processed_data/train/ & processed_data/val/ (Arrow format)

🔧 Pipeline xử lý

1. LOAD: load_dataset("apurvaga/go-browse-wa", split="train")
       hoặc Dataset.load_from_disk("data_local/go-browse-wa")

2. FILTER: Giữ lại trajectory có traj_reward > 0
       → Chỉ học từ trajectory thành công

3. EXTRACT: Lấy step_data (có thể là dict hoặc list)
       → Mỗi sample chứa prompt + completion

4. FILTER: Loại bỏ sample không có prompt/completion hợp lệ

5. FLATTEN: prompt + completion → messages (1 list duy nhất)
       → Chưa apply chat template (để tương thích tokenizer lúc train)

6. SPLIT: Chia train/val (mặc định 95/5)

7. SAVE: Lưu dưới dạng Arrow (định dạng nhanh của HuggingFace datasets)
💡 Lưu ý: Chat template không được apply ở bước preprocess. Nó được apply trong training script để đảm bảo phiên bản tokenizer khớp với model đang train.

4. Full SFT Training — sft_policy.py

[Script] webexp/train/sft_policy.py ⭐ (File chính)

Input:Dataset JSONL đã qua preprocess, Model Qwen2.5-7B-Instruct
Output:Model đã fine-tune full weights (Behavioral Cloning)

🔧 Pipeline huấn luyện

Bước 1: Cấu hình

model_id = "Qwen/Qwen2.5-7B-Instruct"
max_seq_length = 24000              # Cực dài vì trajectory chứa cả axtree
per_device_train_batch_size = 1     # GPU memory hạn chế với seq dài
gradient_accumulation_steps = 4     # Batch hiệu dụng = 4
num_train_epochs = 2
learning_rate = 2e-5
optim = "paged_adamw_8bit"          # Tiết kiệm VRAM

Bước 2: Load & Filter Dataset

dataset = load_dataset('json', data_files=...)
dataset = dataset.filter(lambda x: x['traj_reward'] > 0)  # Chỉ trajectory tốt
         .map(lambda x: x['step_data'])                    # Trích xuất step_data

Bước 3: Chuyển đổi định dạng

flatten_messages(sample):  prompt + completion → ['flattened']
formatting_prompts_func:   ['flattened'] → tokenizer.apply_chat_template → ['text']

Cấu trúc dữ liệu trước khi flatten:

{
  "prompt": [
    {"role": "system", "content": "You are a web agent..."},
    {"role": "user",   "content": "Goal: Find the cheapest product"},
    {"role": "user",   "content": "[AXTree + Screenshot của trang]"}
  ],
  "completion": [
    {"role": "assistant", "content": "{\"thought\": \"...\", \"action\": \"click('a12')\"}"}
  ]
}

Sau khi flatten + apply chat template → 1 chuỗi text duy nhất theo format Qwen ChatML:

<|im_start|>system
You are a web agent...
<|im_end|>
<|im_start|>user
Goal: Find the cheapest product
[AXTree...]
<|im_end|>
<|im_start|>assistant
{"thought": "I should click on...", "action": "click('a12')"}
<|im_end|>

Bước 4: DataCollatorForCompletionOnlyLM

response_template = "<|im_start|>assistant\n"
data_collator = DataCollatorForCompletionOnlyLM(
    response_template=response_template,
    tokenizer=tokenizer
)

Đây là chìa khóa: chỉ tính loss trên token sau <|im_start|>assistant. Tất cả token trước đó (system prompt, user message, axtree) được mask = -100, không đóng góp vào loss → model chỉ học cách sinh action, không học lại prompt.

Bước 5: Train

trainer = SFTTrainer(model=model_id, tokenizer=tokenizer,
                      train_dataset=dataset, data_collator=data_collator,
                      args=trainer_config)
trainer.train()

Sử dụng flash_attention_2, bfloat16, gradient_checkpointing để train được sequence 24K tokens trên GPU.

5. LoRA Fine-tuning — sft_lora.py

[Script] webexp/train/sft_lora.py

Input:Dataset apurvaga/go-browse-wa (trực tiếp từ HF), Model Qwen3.5-9B
Output:LoRA Adapter weights (không phải full model)

Điểm khác biệt so với sft_policy.py

Yếu tốsft_policy.pysft_lora.py
ModelQwen2.5-7B-InstructQwen3.5-9B
Phương phápFull fine-tune (tất cả weights)LoRA (chỉ train adapter)
max_seq_length24,0008,192
Attentionflash_attention_2sdpa (built-in)
PackingFalseTrue (ghép nhiều sample vào 1 sequence)
DatasetJSONL localHuggingFace hub
DataCollatorCó (CompletionOnlyLM)Không (model tự xử lý)

LoRA Config

lora_config = LoraConfig(
    r=16,                    # Rank của ma trận low-rank
    lora_alpha=32,           # Scaling factor
    target_modules=[         # Các layer được fine-tune
        "q_proj", "k_proj", "v_proj", "o_proj",  # Attention
        "gate_proj", "up_proj", "down_proj"       # MLP
    ],
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
💡 Tại sao dùng LoRA? Full fine-tune model 7-9B cần ~50-70GB VRAM. LoRA chỉ train ~0.1% số weights (vài chục MB) trong khi vẫn đạt chất lượng tương đương. Phù hợp khi tài nguyên hạn chế.

6. Production LoRA — train_lora.py

[Script] train_lora.py (phiên bản production-ready)

Input:Processed data từ disk, Model Qwen3.5-9B, toàn bộ tham số qua CLI
Output:LoRA Adapter + DeepSpeed ZeRO-2

Đây là phiên bản hoàn chỉnh nhất cho môi trường production (4×A100 40GB):

python train_lora.py \
  --model_id Qwen/Qwen3.5-9B \
  --train_data_path processed_data/train \
  --val_data_path processed_data/val \
  --max_seq_length 8192 \
  --lora_r 16 --lora_alpha 32 \
  --per_device_batch_size 1 \
  --gradient_accumulation_steps 16 \
  --num_epochs 2 \
  --output_dir outputs/qwen3.5-9b-lora

Hỗ trợ DeepSpeed ZeRO-2 qua accelerate launch --config_file configs/accelerate_config.yaml, phân tán optimizer states & gradients qua nhiều GPU.

7. Cơ chế DataCollatorForCompletionOnlyLM

[Cơ chế] Loss Masking trong SFT

Đây là cơ chế quan trọng nhất của SFT web agent. Hãy hình dung:

Input đầy đủ:
  <|im_start|>system\nYou are a web agent...<|im_end|>
  <|im_start|>user\nGoal: Find product\n[AXTree 15K chars]<|im_end|>
  <|im_start|>assistant\n{"thought": "...", "action": "click('a12')"}<|im_end|>

Loss mask:
  [MASK] [MASK] [MASK] ... [MASK] [MASK]
  [MASK] [MASK] [MASK] ... [MASK] [MASK]
  [TRAIN] [TRAIN] [TRAIN] ... [TRAIN] [TRAIN]

Chỉ token màu xanh được tính loss ↑

Tại sao? Nếu không mask, model sẽ học cả cách sinh ra axtree và system prompt — vừa tốn compute vô ích, vừa làm model "học vẹt" thay vì học cách ra quyết định. Masking đảm bảo model chỉ học cách sinh action từ observation.

Cài đặt trong code:

# Tokenizer tách biệt response_template
response_template = "<|im_start|>assistant\n"

# DataCollator tự tìm vị trí của template trong input_ids
# và mask tất cả token trước đó
collator = DataCollatorForCompletionOnlyLM(
    response_template=response_template,
    tokenizer=tokenizer
)

8. Toàn cảnh Data Flow

🔄 Từ Website → Model

🌐 WEBSITE (vd: Shopping, Gitlab, Reddit, Google Maps)
│
├─ 🔍 Go-Browse Algorithm (web_explore.py)
│   ├─ PageExplorer: "Có thể làm gì trên trang này?"
│   ├─ NavExplorer:   "Có link nào dẫn đến trang khác?"
│   ├─ Feasibility Checker (Solver): "Task này có thực sự làm được không?"
│   └─ Solver:        "Làm task này, ghi lại từng bước"
│
├─ 💾 Trajectory data (JSON, lưu local)
│   └─ Mỗi trajectory: goal + reward + list[{thought, action, axtree, screenshot}]
│
├─ ☁️ Upload lên HuggingFace Hub: apurvaga/go-browse-wa
│
├─ 🔧 preprocess.py
│   ├─ Filter: reward > 0
│   ├─ Extract: step_data → {prompt, completion}
│   ├─ Flatten: prompt + completion → messages
│   └─ Split: train / val
│
├─ 🏋️ Training (sft_policy.py / sft_lora.py / train_lora.py)
│   ├─ Load dataset
│   ├─ Flatten messages
│   ├─ Apply chat template → text string
│   ├─ DataCollatorForCompletionOnlyLM (mask non-assistant tokens)
│   └─ SFTTrainer.train()
│
└─ 🎯 Fine-tuned Model
    └─ Input: goal + webpage → Output: action sequence

📊 Mối quan hệ giữa các DataClass

Graph (1)
 └── Node (*)                         # Mỗi URL là 1 node
      ├── Task (*)                    # Mỗi task có thể làm trên node
      │    ├── Trajectory (+)         # Positive: giải thành công
      │    │    └── TrajectoryStep (*)  # Mỗi step = 1 action
      │    └── Trajectory (-)         # Negative: giải thất bại
      ├── Trace (*)                   # Đường đi từ node cha
      │    └── TrajectoryStep (*)
      └── children: list[url]         # Node con (do NavExplorer tìm thấy)

Sau khi process_for_dataset():
  BrowserGymAgentTrajectoryData
   └── BrowserGymAgentStepData (*)
        ├── thought: str
        ├── action: str
        ├── axtree: str
        └── last_action_error: str | None

Sau khi flatten → training:
  {
    "prompt":     [system_msg, user_msgs...],   # Observation
    "completion": [assistant_msg]               # Action cần học
  }
  → apply_chat_template → "text" string
  → DataCollator masks non-assistant tokens → Compute loss

🧠 Tóm tắt cho dân Competitive Programming

Khái niệm DS&AÁnh xạ sang Go-Browse
BFS trên đồ thịDuyệt web theo chiều rộng: mỗi URL là 1 đỉnh, mỗi link là cạnh
State space searchMỗi Node là 1 state, Task là goal state, Trajectory là path
Greedy + BacktrackingSolver thử action, nếu blocked page → go_back()
Filter + Map/ReduceDataset pipeline: filter(reward>0) → map(extract) → map(flatten) → map(template)
Loss maskingGiống như chỉ tính cost trên 1 đoạn con của dãy, bỏ qua prefix
LoRA (Low-Rank Adaptation)Thay vì update toàn bộ ma trận W (dxd), chỉ update A·B với A (dxr), B (rxd) với r ≪ d
🎓 Lời khuyên cho bạn: Với nền tảng DS&A + OOP, bạn có thể hiểu Go-Browse như một thuật toán tìm kiếm tự động trên đồ thị web, trong đó:
  • Graph = đồ thị các trang web (Node = URL, Edge = navigation)
  • Agent = "oracle" dùng LLM để đề xuất bước đi và đánh giá
  • Training = học behavioral cloning từ các đường đi thành công
  • Loss masking = chỉ học "đoạn quyết định", không học lại input
Hãy bắt đầu đọc code từ webexp/explore/algorithms/web_explore.py (vòng lặp chính), sau đó đến webexp/explore/core/ (cấu trúc dữ liệu), rồi webexp/agents/ (cách agent tương tác LLM), và cuối cùng là webexp/train/sft_policy.py (cách dùng dữ liệu đó để train).
