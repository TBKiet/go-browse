1. Go-Browse là gì?

Go-Browse là một framework Python giúp thu thập dữ liệu huấn luyện cho web agent một cách tự động — không cần con người gán nhãn.

Ý tưởng cốt lõi: cho một AI (LLM) tự động duyệt website → tự nghĩ ra nhiệm vụ → tự thực hiện → tự đánh giá thành công hay thất bại. Kết quả là tập dữ liệu gồm hàng ngàn "trajectory" (chuỗi hành động trên web) dùng để huấn luyện model nhỏ hơn, nhanh hơn.

Input

  • 1 URL gốc (vd: amazon.com)
  • Danh sách URL được phép / bị chặn (regex)
  • Config số lượng agent, model, max steps

Output

  • Đồ thị website (Graph) — các trang + đường đi
  • Hàng trăm Task (nhiệm vụ) đã được kiểm tra khả thi
  • Hàng nghìn Trajectory (chuỗi hành động) dùng để train

3 luồng chính:

LuồngMô tảFile chính
1. Khám pháAI duyệt website, đề xuất task, giải task, mở rộng đồ thịwebexp/explore/algorithms/web_explore.py
2. Tiền xử lýLọc trajectory thành công, trích xuất prompt+completion, split train/valpreprocess.py
3. Huấn luyệnSFT/LoRA fine-tune model nhỏ hơn (Qwen) từ dữ liệu đã xử lýtrain_lora.py, webexp/train/

Framework xoay quanh một đồ thị có hướng biểu diễn website:

3. Vấn đề: trajectory cũ thiếu ngữ nghĩa

Trajectory trước cải tiến chỉ là chuỗi hành động thô, thiếu thông tin để model học hiểu được ý nghĩa của hành động:

Trước — TrajectoryStep cũ

{
  "action": "click('bid_42')",
  "parsed_action": "click('bid_42')",
  "thought": "I need to click...",
  "observation": { "screenshot": ..., "axtree": ... }
}

Thiếu: mô tả tự nhiên, goal đang tiến hóa, tọa độ element, URL tracking, task type.

Sau — TrajectoryStep mới

{
  "action": "click('bid_42')",
  "action_nl": "Click 'Sony WH-1000XM5' in search results",
  "refined_goal": "Find Sony headphones under $350 on Amazon",
  "bounding_box": {"x":245,"y":380,"w":600,"h":24},
  "element_metadata": {"tag":"link","text":"Sony WH-..."},
  "page_url_before": "amazon.com/s?k=sony",
  "page_url_after": "amazon.com/s?k=sony",
  "action_reasoning": "First result matching target product"
}

3 thiếu sót chính:

  1. Không có mô tả tự nhiên — Model chỉ thấy click('bid_42'), không hiểu "click vào nút Search"
  2. Goal tĩnh — Task description được propose một lần rồi giữ nguyên, không được cập nhật khi agent khám phá thêm
  3. Không có visual grounding — Screenshot không có annotation, model không biết element nào tương ứng với số nào

4. 7 Phase cải tiến — Semantic Trajectory

Lấy cảm hứng từ dự án Explorer (ACL 2025 Findings), các cải tiến được chia thành 7 phase, triển khai tuần tự. Tất cả đã hoàn thành.

Phase 1 — Thêm semantic fields vào TrajectoryStep

FileThay đổi
webexp/explore/core/trajectory.pyThêm 7 fields mới: action_nl, refined_goal, action_reasoning, bounding_box, element_metadata, page_url_before, page_url_after
webexp/agents/solver_agent.pyParse action_in_natural_language và refined_goal từ LLM response; extract element metadata từ axtree
webexp/agents/prompt_builders/solver_prompt_builder.pyPrompt yêu cầu LLM output thêm 2 field JSON mới

Đã xong 23 tests

Phase 2 — Task Refinement (goal tiến hóa)

Goal được cập nhật ở mỗi bước khi agent tương tác với website. Ví dụ:

Step 0: "Find a product on Amazon" (mơ hồ) Step 2: "Find a coffee maker on Amazon" (có category) Step 4: "Find a coffee maker under $100 with 4+ stars" (có constraints)

Đã xong 6 tests

Phase 3 — Task Summarization (tóm tắt hậu trajectory)

Agent mới TaskSummarizationAgent — sau khi trajectory kết thúc, gọi GPT-4V để tạo mô tả task hoàn chỉnh từ toàn bộ action history + screenshots. Đảm bảo task description khớp với những gì thực sự đã làm.

Đã xong 4 tests 1 file mới

Phase 4 — Set-of-Mark Visual Grounding

Port code SoM từ Explorer: screenshot được overlay với numbered tags → mỗi interactive element có một số → agent reference bằng [idx]. Cầu nối giữa pixel và text.

Đã xong 5 tests 3 files mới

Phase 5 — Enhanced Verification

Evaluator không chỉ trả về success/failure mà còn phân loại task type (Transaction / Information seeking / Site navigation / Content modification) và đưa ra failure reason nếu thất bại.

Đã xong 4 tests

Phase 6 — Better Task Proposal

Cải thiện prompt cho PageExplorerAgent: yêu cầu format chuẩn, thêm constraints (budget, rating, location...), ví dụ cụ thể.

Đã xong

Phase 7 — CAPTCHA Detection

Agent mới CaptchaDetectionAgent — tự động phát hiện CAPTCHA pages để skip, tránh lãng phí LLM calls.

Đã xong 1 test 1 file mới

6. Tổng kết: Trước vs Sau

Khía cạnhTrước cải tiếnSau cải tiến
Action representation Chỉ raw action (click('bid_42')) Dual: raw + natural language + reasoning
Task goal Tĩnh — propose một lần Tiến hóa — refined mỗi step + summarized hậu kỳ
Visual grounding Không có Set-of-Mark — numbered tags trên screenshot
Trajectory evaluation Binary success/failure Success/failure + task type + failure reason
Element metadata Không có Tag, text, role, bounding box
URL tracking Không có per-step URL page_url_before + page_url_after mỗi step
CAPTCHA handling Không có — lãng phí LLM calls Tự động detect & skip
Backward compatibility — Old format load đúng (None defaults), old add_step() vẫn hoạt động
Test coverage 0 tests 66 tests — parsing + model + edge cases + integration
Điểm cốt lõi: Mỗi trajectory giờ đây không chỉ là chuỗi hành động mà còn là một bản ghi có ngữ nghĩa đầy đủ — model có thể học được cả "làm gì" (action), "tại sao" (reasoning), "ở đâu" (bounding box), và "mục tiêu đang là gì" (refined goal). Điều này giúp dữ liệu huấn luyện chất lượng cao hơn đáng kể.
